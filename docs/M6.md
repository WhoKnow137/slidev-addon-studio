# M6 structural transaction contract

This fork adds structural operations for generated Slidev projects that carry
`data/slides/index.json` and canonical page imports in `slides.md`. Hand-authored
import structures are refused when their ownership cannot be established.

## Commit protocol

`node/structural-service.ts` constructs a complete candidate from captured file
revisions and uniquely resolved managed roots. It validates slide/index order,
managed IDs, supported capabilities, resource references and every candidate
page. `node/structural-transaction.ts` takes the sorted changed-path set plus
read-only revision guards under one project-wide lock. Text and layer edits use
that same lock. Every expected revision is checked before staging and again
before commit.

The store writes before/after bytes and a `prepared` manifest under
`.studio-structural/transactions/<uuid>/`, syncing staged files. It then marks
the manifest `committing` and atomically replaces each target. It marks
`complete` after all replacements. An interruption before `committing` discards
unreachable staging. An interruption during `committing` rolls forward after
verifying every target is exactly its old or new hash and every staged new blob
matches its recorded hash. An unexpected target, corrupt blob, or unknown
journal is reported as unresolved and blocks further structural writes.
Individual renames are atomic; a multi-file state can be briefly mixed during
the commit window, so recovery is required before serving managed edits after
a crash. External editors do not take this lock; their changes are detected by
revision checks, and a race after the final check remains possible.

One successful operation adds one session history entry containing all before
and after bytes. Undo/redo apply the inverse through the same journal and
revision guards. Text, layer and structural entries share chronological order.
Session history is in memory and does not survive server restart; journal
recovery restores disk consistency, not the previous session's undo stack.

## Identity and provenance

Local IDs use a monotonic `local-m6-XXXXXXXX` counter in
`data/structural-provenance.json`. Allocation checks current managed source;
tree duplicates receive new IDs for every managed tag. The overlay records
imported vs local duplicate origin, tombstones, moves, reparenting, reorder and
source removal. It remains separate from converter source provenance. Converter
reruns preserve local structural states and report source/local conflicts.

`data/resource-reachability.json` records page references. Exact media bytes
are immutable; `stageImmutableResource` requires a signature-matching media
blob plus a source and reachability candidate in the same plan. It checks
existing content-addressed bytes and refuses overwrite. Deleting one object
does not delete a shared resource.

## Supported operations

`POST /@studio/structural` takes `{action,session,expectedRevision}`. The
session is the same browser session used for text/layer source history.
`action` supports:

- `{kind:"object",action:"delete"|"duplicate",slideId,id}`
- `{kind:"object",action:"reorder",slideId,id,beforeId}`
- `{kind:"object",action:"move",slideId,id,toSlideId}`
- `{kind:"object",action:"reparent",slideId,id,parentId}` for a root managed
  layer under a simple managed frame with invertible rotation/translation
- `{kind:"slide",action:"duplicate"|"delete",slideId}`
- `{kind:"slide",action:"reorder",slideId,beforeSlideId}`; omit
  `beforeSlideId` to place it last

`GET /@studio/structural` or `GET /@studio/deck` returns current revisions and
active slide IDs. The existing `/@studio/deck` UI route maps generated-project
duplicate/remove/move to the structural service. Generated slide insertion
without a defined template is refused. A safe root can contain unowned
render-only descendants, but unsupported component, instance, constraint,
affine or ambiguous ownership operations are refused with an explicit reason.
This milestone does not define Figma-native component swap/detach, paint,
crop, vector point, auto-layout or media replacement behavior.

Use `StructuralTransactionStore.recover()` on startup and before converter
reruns. Do not remove `.studio-structural/transactions/` by hand when recovery
reports an unresolved transaction; inspect its manifest and affected hashes.
